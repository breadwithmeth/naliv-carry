# Анализ и исправление вылетов/зависаний Telegram Mini App

## Причины (по результатам анализа кода)

1. **Монолитный бандл ~1.5 МБ** (`dist/assets/index-*.js`), все 9 страниц импортируются eagerly (`src/routes/AppRouter.tsx:6-14`), нет `React.lazy`/`Suspense`. Полный antd + иконки + legacy-полифиллы парсятся при каждом холодном старте в Telegram WebView — на слабых Android это секунды фриза/джанка. **Главная причина зависаний.**
2. **Нет `window.onerror` / `unhandledrejection`** — асинхронные ошибки (экшены сторoв, таймеры, SW) невидимы и проявляются как тихий фриз/белый экран.
3. **`vite:preloadError` → `window.location.reload()`** (`src/main.tsx:10-13`) — возможен бесконечный цикл перезагрузок при устаревшем SW-кэше (sw.ts отдаёт старый index.html, ссылающийся на несуществующие чанки).
4. **telegram-web-app.js грузится синхронно с telegram.org** (`index.html:14`) — сетевая зависимость при старте; при отсутствии `initData` приложение падает с ошибкой в `src/utils/telegram.ts:14`.
5. **BrowserRouter в Telegram WebView** — свайп «назад» закрывает Mini App (выглядит как вылет); BackButton из Telegram не используется.

## План исправлений

### 1. Код-сплиттинг по маршрутам
- `src/routes/AppRouter.tsx`: перевести все страницы на `React.lazy(() => import(...))`, обернуть `Routes` в `<Suspense fallback={<PageLoader/>}>` (использовать существующий antd Spin-паттерн из `ProtectedRoute`).
- Проверить сборку: чанк по странице, index-чанк должен уменьшиться в несколько раз.

### 2. Глобальная обработка ошибок + локальный журнал
- Новый `src/utils/errorLog.ts`: кольцевой буфер последних N (напр. 30) ошибок в localStorage (`app_error_log`): timestamp, message, stack (урезанный), source (onerror / unhandledrejection / boundary / api).
- В `src/main.tsx`: подписка `window.addEventListener('error')` и `('unhandledrejection')` → запись в журнал. Фильтровать повторяющиеся подряд ошибки, чтобы не заспамить хранилище (rate-limit: не более 1 записи в 2 сек на одинаковое сообщение).
- Экран ошибки `AppErrorBoundary` и/или страница профиля: показать кнопку «Показать журнал ошибок» — вывод последних ошибок (для отправки скриншотом).

### 3. Защита от цикла перезагрузок
- В `src/main.tsx` обработчик `vite:preloadError`: записывать в sessionStorage метку; если перезагрузка из-за preloadError уже была за последние ~10 секунд — не перезагружать, а показать сообщение/оставить текущий UI. При перезагрузке — сначала попытаться очистить устаревший SW-кэш (`caches.keys()` / `registration.update()`), а не просто reload.

### 4. Устойчивость к отсутствию Telegram SDK
- В `index.html` добавить `defer` не требуется (нужен до app), но сделать graceful fallback: в `src/hooks/useTelegramMiniApp.ts` и `getTelegramInitData` — при отсутствии `window.Telegram` не падать сразу, а показать понятный экран/продолжить работу в браузере (уже частично есть в LoginPage — проверить и смягчить ошибку вместо throw в кейсе, когда скрипт просто не успел загрузиться: ретрай через микрозадержку).

### 5. BackButton + свайпы (UX-«вылет»)
- В `useTelegramMiniApp.ts`: интегрировать `BackButton` — показывать на вложенных маршрутах (`/orders/:orderId`, `/shifts/payment-report`, `/map`, `/profile`), onClick → `history.back()`.
- Оставить `disableVerticalSwipes` как есть.

## Не делаем
- Sentry/внешняя телеметрия (по выбору пользователя — локальный журнал).
- Миграцию на @telegram-apps/sdk — рискованный рефакторинг, сырой API работает.

## Проверка
- `npm run build` — убедиться в код-сплиттинге и уменьшении index-чанка.
- Ручная проверка: запуск в браузере, проверка fallback при отсутствии Telegram, проверка экрана ошибки и кнопки журнала.
